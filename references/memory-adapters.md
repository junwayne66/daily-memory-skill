# Memory Adapters

Use this reference to write Daily Memory into the active agent's own memory system without duplicating or polluting long-term bootstrap memory.

## Adapter Selection

Detect the active platform from user input, environment, config, or filesystem:

- OpenClaw: `OPENCLAW_*`, `~/.openclaw/workspace`, OpenClaw memory tools, or OpenClaw docs/config.
- Hermes Agent: `HERMES_HOME`, `~/.hermes`, `hermes memory status`, or `~/.hermes/memories`.
- Codex: `~/.codex/memories`, workspace instructions, or Codex memory tooling.
- Generic: no native memory detected.

If multiple agents need the same Daily Memory knowledge, designate one authoritative working directory. Let the archive agent run the loop pipeline and write the canonical vault, and let other agents read it through native search extra paths, symlinks, provider collections, or the generated bridge notes. Do not merge all agents into one workspace just to share memory.

## The Vault Is The Search Surface

The knowledge vault (`knowledge/`) is plain Markdown with frontmatter and wikilinks, so it doubles as the retrieval surface: point any reader agent's memory search at the `knowledge/` directory and both entity notes and generated bridge notes become searchable. There is no separate deep/shallow split to maintain:

- `knowledge/Events|People|Organizations|Projects|Topics/*.md`: curated entity notes (source of truth).
- `knowledge/Daily/YYYY-MM-DD.md`: episodic daily notes.
- `knowledge/daily-memory-YYYY-MM-DD.md`: compact bridge notes generated by `memoryctl index` at the vault root, for platforms whose search only indexes shallow paths reliably.
- `index/edges.json`, `state/`: engine-derived data; exclude from memory indexing when the platform allows path filters.

## OpenClaw

OpenClaw's memory model is a strong fit for Daily Memory:

- `MEMORY.md`: compact curated long-term facts, decisions, preferences, and standing instructions.
- Memory search can combine semantic and keyword retrieval when providers are configured.
- In current OpenClaw layouts, shallow Markdown files are the safest bridge for reader-agent search; the generated bridge notes at the vault root cover this case.

Recommended working directory for a dedicated Daily Memory archive agent:

```text
~/.openclaw/workspace-daily-memory/
  MEMORY.md
  sources/<family>/YYYY-MM-DD__<id>.md
  knowledge/
    Events/  People/  Organizations/  Projects/  Topics/  Daily/
    daily-memory-YYYY-MM-DD.md
  state/        # engine state, not memory
  index/edges.json
  runs/YYYY-MM-DD/run_manifest.yaml
  reports/YYYY-MM-DD.md
```

Promote only compact, durable, high-confidence items to root `MEMORY.md`. Include action-sensitive boundaries when the fact affects future behavior, approvals, handoffs, expiry, or safe-to-act timing.

Recommended sharing pattern when the main Feishu bot agent should answer from Daily Memory:

```json5
{
  agents: {
    list: [
      {
        id: "main",
        memorySearch: {
          extraPaths: [
            "/home/botinkit/.openclaw/workspace-daily-memory/knowledge"
          ]
        }
      },
      {
        id: "daily-memory",
        workspace: "/home/botinkit/.openclaw/workspace-daily-memory",
        skills: ["daily-memory-skill"]
      }
    ]
  }
}
```

After scheduled archive writes, reindex both the archive agent and any reader agent that depends on `extraPaths`.

Useful checks when available:

```bash
openclaw memory status
openclaw memory index --agent daily-memory --force
openclaw memory index --agent main --force
openclaw memory search --agent main "daily-memory-<date>"
```

Do not treat indexing as successful until retrieval is proven through the same agent that will answer the user. A minimal verification sequence is:

```bash
openclaw memory index --agent daily-memory --force
openclaw memory index --agent main --force
openclaw memory status --agent main --deep
openclaw memory search --agent main "<bridge note title or event title>"
```

If search returns empty results while files/chunks exist, or if logs mention missing index metadata/provider state, record it as an OpenClaw memory-search defect in:

- `runs/YYYY-MM-DD/run_manifest.yaml`
- `reports/YYYY-MM-DD.md`
- the owner delivery summary, if delivery is enabled

Do not claim that the main Feishu bot can search the new memory until a query returns the bridge note or a relevant chunk.

## Hermes Agent

Hermes has small built-in memory files and optional external memory providers.

- Built-in memory lives under `~/.hermes/memories/`.
- `MEMORY.md` stores compact agent notes such as project conventions, tool lessons, and durable work facts.
- `USER.md` stores user profile and preferences.
- Built-in memory is injected as a frozen snapshot at session start; updates persist immediately but may not appear in prompt context until a later session.
- The memory tool usually supports add, replace, and remove rather than direct read.
- External providers such as Honcho, Mem0, or others are additive; built-in memory remains active. Hermes typically enables one external provider at a time.

Recommended mapping:

```text
~/.hermes/
  memories/
    MEMORY.md          # pointers + durable lessons only
    USER.md
  daily-memory/        # full loop workspace (workdir)
    sources/
    knowledge/
    state/
    index/
    runs/
    reports/
```

Do not store raw transcripts or large project files in Hermes built-in memory. Store the full Daily Memory workspace in the external folder or active provider. Add only 1-3 compact memory entries when a durable lesson, project invariant, or recurring user preference should be visible in future sessions, plus a pointer like "Daily Memory vault: ~/.hermes/daily-memory/knowledge".

Useful checks when available:

```bash
hermes memory status
hermes memory setup
hermes memory off
```

If an external provider is active, use it for searchable semantic recall. Keep source ids and file paths so provider facts remain auditable.

## Codex

When running in Codex, follow the active memory instructions from the environment. Prefer project-local artifacts for Daily Memory details and only update Codex durable memory when the user explicitly asks to remember something or when the environment's memory policy permits it.

Recommended project-local mapping:

```text
<workspace>/.daily-memory/   # workdir
  sources/
  knowledge/
  state/
  index/
  runs/
  reports/
```

## Generic Agent

When no native memory exists, the workspace layout from [schemas.md](schemas.md) is already portable: plain Markdown vault, JSON state, YAML run manifests. The vault can be opened directly in Obsidian. Add SQLite or vector search on top only when the volume justifies it; the engine does not require either.

## Promotion Strategy

Promote memory in this order:

1. Raw evidence: sync loops save source snapshots under `sources/` with provenance frontmatter.
2. Knowledge vault: the graph loop merges events, people, organizations, projects, topics, decisions, risks, and closure state into entity notes; the daily note records the episodic delta.
3. Bridge note: generated deterministically by the index loop for shallow-search readers.
4. Native long-term memory: add compact durable items to `MEMORY.md` only when they are useful in many future sessions.

Every promotion must preserve source references and confidence. If a new item conflicts with an old memory, write a `## Conflicts` entry and ask the user or source owner to confirm before overwriting.

## Cross-Agent Sharing

For OpenClaw + Hermes or multi-agent setups:

- Keep one canonical Daily Memory working directory.
- Let each agent write pointers to the canonical vault in its native memory.
- The engine's deterministic state and idempotent loops let multiple schedules coexist without duplicate processing; still avoid two agents draining the same loop pipeline concurrently.
- Avoid direct writes into another agent's private memory database unless that agent exposes an official memory tool or provider API.
- Verify delivery and recall: after a cross-agent write, query/read through the same channel the target agent will use.
